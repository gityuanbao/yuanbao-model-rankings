# 鹈鹕测试榜维护

页面地址为 `/pelican/`，导航顺序为价格排行榜、性能排行榜、鹈鹕测试榜。

标题为“鹈鹕测试，从夯到拉排名”，副标题为“仅供娱乐”。在收到用户的测试表格前，数据保持为空，不推测模型成绩。

当前执行[源宝鹈鹕送宝挑战 v2.0](PELICAN-BENCHMARK-v2.md)：只生成一次，使用最高可设置的推理档位，无法设置最高档时用默认档；统一 20 秒送宝题目。测试者提交原作与型号信息，AI 助手逐项评分，源宝复核后发布。完整提示词见[统一提示词 v2.0](鹈鹕测试_统一提示词_v2.0.txt)。旧 v1 文件仅作归档，不再执行三次取中位数规则。

页面沿用价格榜、性能榜的整体结构与样式：全部 12 家厂商 Logo 快捷入口、前三名大卡片、模型搜索与厂商多选侧栏、榜单面板及分享入口。只有排名列采用从夯到拉的竖向等级条。没有结果时保留三个待公布卡片；卡片跟随当前筛选，展示顺序反转不会改变前三名。

## 表格与排序

测试者只需交回原作、实际型号、日期、平台、档位截图与工具使用情况，无需填写分数或旧 Excel。AI 助手按 v2 的 16 项规则评分、应用分数上限、记录扣分依据；待源宝复核作品与记录后再整理厂商、档位、同档顺序与 GIF。不能根据价格或性能成绩推断鹈鹕成绩。没有完整响应的请求不定档，证据不足的评分先待核实。

编辑 `src/data/pelican.json` 的 `entries`，每条记录包含：

| 字段 | 内容 |
| --- | --- |
| `id` | 唯一测试 ID，小写英文、数字与连字符 |
| `name` | 显示的模型名称，可带版本或测试配置 |
| `providerId` | 复用 `src/data/catalog.json` 的厂商 ID 与彩色 Logo |
| `tier` | `hang` 夯、`top` 顶级、`good` 人上人、`npc` NPC、`la` 拉 |
| `order` | 同档位从上到下的顺序，正整数，同档不能重复 |
| `gif` | `media/pelican/文件名.gif`，实际文件放入 `public/media/pelican/` |

相同模型的不同测试可以有独立 ID；本榜独立维护，不要求先收录到价格榜，也不改动价格或性能数据。新厂商须先补齐厂商资料和 Logo。

上表是当前空榜的展示结构，不代表完整评测记录已经实现。首批导入前需补齐规则版本、实际型号与档位、测试日期、工具条件、逐项分数和证据的保存与展示；同分应标为并列，工具条件不同的记录分别比较。作品失败要明确标失败，不能伪造模型 GIF 来满足路径字段。收到真实原作后再完成这些扩展，当前不写入虚构记录。

页面默认按固定档位从夯到拉排列，同档按 `order` 升序；用户可切换从拉到夯查看。搜索、厂商与显示方向保存在 URL，可分享并在前进、后退时恢复。GIF 保持原比例完整展示，点击可打开原图，手机自动折行。空档位保留位置；筛选无匹配时显示清除筛选入口。

录入后运行 `npm test`、`ASTRO_TELEMETRY_DISABLED=1 npm run build` 和 `npm run validate:build`。构建会校验条目字段、重复 ID 和档位内排序；产物检查会验证本地 GIF 链接存在以及 GitHub Pages 子路径。随现有 Pages 工作流部署，无新增服务器。
