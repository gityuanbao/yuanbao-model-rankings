## 评分与确认

满分 100，11 小项：白猫形象 20、自行车结构 20、骑车关系 30、画面完成度 20、网页与 SVG 10。10 分项用 0 / 5 / 10；5 分项用 0 / 2.5 / 5。每个扣分项写具体原因，能定位时保留录屏时间点。同一问题不重复扣分，静态不直接加减分，不按装饰多少评分。

GIF 能支持的是可见画面观察分 /90。“网页可以展示”和“主体使用 SVG”的 10 分须核验原始 HTML 或完整代码；不把待核验记 0，不换算成 /100，不提前定档。其他看不清的项同样标待核实。完整原作确认无法展示有效画面且排除环境问题后才能记作品失败；网络、权限或请求超时只记待补测。

AI 助手逐项给分、注明依据并核对元数据，源宝复核作品和记录后才能转为正式成绩。正式总分为 11 项直接相加，对应夯 90–100、顶级 75–不足 90、人上人 60–不足 75、NPC 40–不足 60、拉低于 40。同分并列，不靠录入顺序拉开差距。不同题目和规则版本不混排。

本批评分标准在收件后补充，正式评分前固定口径；后续不根据某个模型的表现改变权重。缺资料可补交，不要求为了新版手册重测已经完成的作品。

## 数据录入

编辑 `src/data/pelican.json`，顶层使用 `schemaVersion: 2`、`ruleVersion: "3.0"`。每条 `entries` 记录包含：

| 字段 | 内容 |
| --- | --- |
| `id`、`name`、`providerId` | 唯一测试 ID、显示型号、已有厂商 ID；复用彩色 Logo |
| `ruleVersion` | 本批为 `3.0`，防止混用旧题目成绩 |
| `media` | `type: "video"`，视频 `media/pelican/{id}.mp4`、预览图 `media/pelican/{id}.webp` 及真实宽高；文件位于 `public/media/pelican/` |
| `test` | 型号标签、平台、档位、测试日期、工具状态、代码是否改过、型号确认、首次生成、提示词核实与备注 |
| `assessment.status` | `provisional` 为初评待核验，`verified` 为完整核验并经源宝确认 |
| `assessment.criteria` | 11 个评分小项；保存 ID、得分、具体理由与可见证据时间点，未核验用 `null` |
| `assessment.reviewedAt`、`assessment.reviewer` | 真实初评日期与评分者；不能当成实际测试日期 |
| `assessment.ownerConfirmed` | 源宝是否复核确认；不能由导入动作或发布请求推断为已确认分数 |

评分项 ID 依次为 `cat_shape`、`cat_white`、`bike_identity`、`bike_connections`、`rider_support`、`front_paws`、`rear_paws`、`composition`、`visual_finish`（各 10 分），`html_render`、`svg_source`（各 5 分）。最后两项在 `provisional` 时必须为 `null`。总分与档位由核验后的分数计算，不另存手工排序。

型号和设置只填写证据确认的内容；不因规则要求最高档就填“已使用最高档”。平台、档位、日期与是否改代码未知时用 `null`；工具未知为 `unknown`，确认未用为 `none`，开启为 `enabled`。日期格式为 `YYYY-MM-DD`，不从文件修改时间猜实际测试日期。进入 `verified` 前须完成 11 项评分、`ownerConfirmed: true`、`identityStatus: "verified"`、非空平台/档位/日期、已知工具状态，以及 `codeModified: false`；不能手工编造总分或档位绕过门槛。

相同型号的不同配置可有独立 ID。鹈鹕作品不要求已收录价格榜，录入不改动价格或性能数据。新厂商须先补齐资料和图形 Logo。

正式成绩还必须满足 `firstAttempt: true`、`promptStatus: "exact"`。`promptStatus: "variant"` 必须保留 `promptText` 实际原文，不能混入同题正式排名。本批 GLM 截图提示词以“做一个”开头，页面保留差异；Qwen 的 0902 和 DeepSeek Pro 的 0813 后缀目前仅来自回传表。

`data/pelican/submissions-2026-09-14.json` 保存原 GIF 映射、SHA-256、帧数、时长及视频/封面校验值；`reviews-2026-09-14.json` 保存初评依据和截图证据转录。后续补交材料保留这次初评记录，更新展示数据时注明修订依据。`npm run validate:data` 同时校验鹈鹕 schema、资源哈希和证据时间点，生产构建也检查视频与封面路径。

## 排序、分享与验收

正式结果按总分从高到低定档，同分并列；支持反向查看，前三卡片仍取当前筛选的最佳正式作品。初评只展示观察分和待核验状态，不混入正式名次。搜索、厂商及显示方向写入 URL，刷新、前进后退和分享可恢复。

录入后运行 `npm test`、`npm run check`、`ASTRO_TELEMETRY_DISABLED=1 npm run build` 和 `npm run validate:build`，验证 schema、同分、初评隔离、实际资源与 GitHub Pages 子路径。实际检查桌面/手机筛选、作品播放/暂停、评分展开及提示词复制；最终运行证据单独记录，不把说明文档视作测试结果。

随现有 Pages 工作流部署，无新增服务器或自动评分后台。用户补交原作与资料后继续核验，再由源宝确认正式上榜。
