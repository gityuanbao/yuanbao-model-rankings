# 源宝鹈鹕骑车测试 · 首批执行方案 v1.0

方案日期：2026-09-12。状态：测试方案与候选名单，尚未生成或评定任何模型作品。

建议首批测试 **12 款模型、10 家厂商，每款独立生成 3 次，共 36 次正式样本**。准备时间不足时，可先测名单中的前 10 款，保留相同规则。

本榜衡量模型一次生成 SVG 动画代码的表现，重点是形状、空间关系与动作协调。它是“仅供娱乐”的专项测试，不代表模型综合能力。

**题目来源与本榜口径**

Simon Willison 的公开原题是“Generate an SVG of a pelican riding a bicycle”。原题没有要求动画。本方案增加了统一画布、6 秒循环与骑乘动作约束，属于源宝自定的动画版；不能声称与原版测试采用相同题目或权威评分。[原项目](https://github.com/simonw/pelican-bicycle)

候选名单参考近期官方型号与 [Code Arena 的 WebDev 榜单](https://arena.ai/leaderboard/code)（本次读取日期为 2026-09-12，榜单标注 2026-09-11）。Arena 只用来寻找候选，不把它的名次、成绩或带工具的评测结果搬成本榜成绩。

**统一测试题**

以下内容对每个模型逐字相同。单独的可复制版本见同目录“鹈鹕测试_统一提示词_v1.0.txt”。

```text
请用代码制作一段“鹈鹕骑自行车”的二维矢量循环动画。

输出要求：
1. 只输出一个完整、可直接保存为 index.html 并在浏览器中打开的 HTML 文件，不要解释，也不要使用 Markdown 代码围栏。
2. 所有图形都使用内联 SVG 绘制；允许内联 CSS 和原生 JavaScript。不得使用 Canvas、外部库、联网资源、图片、视频、Base64 素材、Emoji 或图标字体来替代绘制。
3. 画面固定为 800 × 600 像素，SVG 的 viewBox 为“0 0 800 600”，页面无边距、无滚动条。背景简洁，主体完整且清晰可见。
4. 页面打开后自动播放。整个画面的动画以 6 秒为一个完整周期，无限循环，循环接缝自然，不需要点击任何按钮。

画面与动作要求：
1. 主角是一只从侧面可辨认的鹈鹕，具有明显的长嘴、嘴下的喉囊、鸟类身体、翅膀和两条腿。
2. 鹈鹕坐在一辆朝右的普通双轮自行车上。车轮、辐条、车架、前叉、车把、车座、曲柄与脚踏板应当清晰可辨，连接关系合理。
3. 鹈鹕的身体与车座保持接触，用翅膀扶住车把；两只脚分别跟随两个脚踏板连续踩踏，双腿自然屈伸，不能在空中乱蹬或穿过车架。
4. 曲柄持续转动，两个脚踏板保持相对位置；两个车轮围绕各自轮轴旋转，方向与向右骑行一致。
5. 可以让主体保持在画面中央，用地面或背景移动表达前进；不要求整辆车横穿画面。
6. 允许适度的身体起伏和装饰，但鹈鹕与自行车的基本结构必须保持稳定，不能脱节、闪烁、突然变形或移出画面。
7. 配色和造型风格自行决定。画面中不要出现模型名称、评分、标题或解释文字。

请直接输出完整 HTML 代码。
```

**评分：100 分**

先看正常速度，再用慢放检查脚、踏板、曲柄和轮轴。每个 10 分小项按“明显不满足 0 / 部分满足 5 / 完整满足 10”给分；每个 5 分小项按“0 / 2 / 5”给分。只对提示词中要求的内容计分，不要求特定配色、装饰、链条或背景。

| 维度 | 分值 | 可检查的小项 |
| --- | ---: | --- |
| 骑乘与动作关系 | 30 | 身体落在车座上、翅膀接触车把，骑姿稳定（10）；两脚持续跟随各自踏板、腿自然屈伸，没有明显脱离或穿插（10）；两个踏板随曲柄保持相对位置，车轮围绕正确轮轴转动且方向协调（10）。 |
| 鹈鹕辨识度 | 20 | 长嘴与嘴下喉囊清晰，不依靠文字说明来辨认（10）；鸟的头颈、身体、翅膀与两条腿完整，比例能辨认为鹈鹕（10）。 |
| 自行车结构 | 20 | 两个车轮与辐条清晰，形状和轮轴稳定（10）；车架、前叉、车把、车座、曲柄与脚踏板的连接关系合理，没有悬空或明显错接（10）。 |
| 动画完整度 | 10 | 动作持续、无明显卡顿闪烁或部件跳变（5）；完整画面在 6 秒接缝处自然衔接（5）。 |
| 画面表现 | 10 | 主体完整、构图清楚，小图仍能辨识关键动作（5）；配色与线条协调、视觉风格一致（5）。简洁画法同样可以满分。 |
| 运行与规范 | 10 | 原始代码直接打开即可自动播放、无影响观看的运行错误（5）；遵守单 HTML、内联 SVG、800×600、无额外文字等交付要求（5）。 |
| 合计 | 100 | 记录每个维度的分数，再执行下方门槛。 |

必须先固定的门槛：
- 没有可渲染作品、完整回答仅拒绝作答，或用现成图片 / 视频、生成图片工具、外部资源代替代码绘制：该次 **0 分**，记录具体原因。
- 只有静态画面，或只有装饰在动而鹈鹕与自行车完全不动：该次最高 **39 分**。
- 有动画，但缺少鹈鹕或自行车、主体明显分离，或看不出连续踩踏：该次最高 **59 分**。
- “夯”除总分至少 90，还要求骑乘与动作关系至少 25 分、动画完整度满 10 分；不满足时该次最高 89 分。
- 多个门槛同时触发时取最低上限。页面标题、代码中声称“这是鹈鹕”不能弥补实际画面缺陷。

评分操作建议：至少由同一个人评完首批所有作品；更稳妥的是两人独立盲评后取平均，分差超过 10 分时共同复看并记录原因。隐藏厂商名、随机打乱样本，评分完成后再恢复对应关系。原始分、门槛上限和最终分分别保存。

**从分数映射到“夯到拉”**

| 档位 | 分数范围（执行门槛后的分数） | 观看感受 | 网站 tier |
| --- | --- | --- | --- |
| 夯 | 90–100 | 一眼是鹈鹕，确实在骑车，结构、动作和循环都成立 | `hang` |
| 顶级 | 75 ≤ 分数 < 90 | 完成度高，有少量动作或细节瑕疵 | `top` |
| 人上人 | 60 ≤ 分数 < 75 | 核心任务成立，骑姿、结构或循环有明显不足 | `good` |
| NPC | 40 ≤ 分数 < 60 | 能看懂主题，但关键骑行动作或形态明显出问题 | `npc` |
| 拉 | 0 ≤ 分数 < 40 | 静态、严重失败，或没有合格作品 | `la` |

每款模型取 3 次最终得分的中位数定档，网站展示中位数所对应的那次 GIF，另外两次原作和分数留档。分数相同时先按骑乘与动作关系、再按动画完整度排序；仍同分时仅按模型名称稳定展示，不宣称存在实力差距。中位样本不唯一时依次按上述维度、生成序号确定，不能临时挑画面。

如果中位样本为 0 分且没有可展示动画，原始失败记录照常保留，网页导入时另做明确写着“未生成有效作品”的结果占位图；占位图不能冒充模型生成物。当前网站要求每条记录有 GIF，因此这种情况需要在导入时单独处理，不能拿空路径填充。
