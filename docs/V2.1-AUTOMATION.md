## 完整链路

`update-prices.yml` 每 6 小时、UTC 分钟 17 执行，支持手动指定 provider 和确认 ID。通过与本地相同的 `prices:update -- --apply` 入口完成：

1. 读取已有 catalog、history、独立汇率和匹配当前价格哈希的上轮状态。
2. 并发度 3，仅请求对应厂商官方 HTTPS 来源；限制超时、响应大小与重定向。
3. 各 Adapter 定位自己的标准价格表，统一到原币 / 百万 Token，再执行 Zod 校验。
4. 对比原币价格和计费元数据。忽略汇率、文案顺序、核验时间等非价格变化。
5. 安全变化进入候选；异常保留旧价，写入 old/new/比例/来源及确认 ID。
6. 追加历史；先在工作区暂存候选，执行工作流检查、全部测试、Astro Build、静态链接检查，失败恢复数据文件。
7. 只有存在有意义的价格/计费元数据变化才准备本地 Git commit。
8. 部署已验证的 Pages artifact；成功后才推送数据 commit。失败不推进默认分支价格。
9. 每轮状态保存到 Actions artifact，不制造仅修改时间戳的提交；普通代码部署也恢复匹配的最近状态。

机器人提交不会被用来隐式触发下一次部署，部署就在更新 workflow 内完成。这避免依赖 GITHUB_TOKEN 事件的递归触发行为，参见 [GitHub 官方说明](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow)。

两个发布 workflow 共用 `pricing-update` 互斥组，并在部署前核对默认分支没有被外部提交推进。最终 push 只允许快进。Pages 与 Git 是两个外部操作；若 Pages 已成功而随后 push 因分支保护或网络失败，任务会报错，线上是刚通过校验的新版本，默认分支仍保留旧数据，可从 `pricing-candidate-data` artifact 恢复完整候选数据后推送，或重跑。该候选备份在部署前保存。无法宣称这两个外部系统具有跨系统原子事务。

## 安全规则与审核

- 必须有明确的模型标识、原币单位、标准输入/输出列与官方域名；缓存、免费额度、Batch 不能充当标准价。
- 标准输入/输出为 0、缺失字段、非法来源、未知结构：阻止，不可用确认 ID 绕过。
- 超过 60% 波动、降至旧值 20% 以下、缓存新增/消失/归零、长输入阶梯、币种、来源、名称/API 版本、状态、促销、时段等变化：人工审核。
- 同厂商超过 50% 已收录模型异常或缺失时，该厂商所有新值进入审核，其他厂商独立处理。
- 未来生效的官方价格不提前发布。
- 审核 ID 绑定旧模型、候选价格、来源和计费证据；旧值或候选改变则拒绝过期确认。
- 异常 PR 只保存报告，不能通过合并报告发布价格。确认后通过 workflow_dispatch 重新抓取并放行精确候选。
- 新模型须人工补齐地区、规格、适用场景和状态。已有模型从页面消失只代表无法解析，不能自动当作下架。

完整操作步骤见根目录 README。手动调价必须运行 `prices:record-manual`，否则当前价与历史不一致会导致构建失败。

## 价格历史与页面

- 迁移保存 24 个初始快照，包括旧索引记录和已下架模型，并明确区分初始快照与真正调价。
- 官方原币费率和全部阶梯保留，包含缓存、Batch、低峰、促销条件；汇率变化不写入调价历史。
- 详情显示当前输入/输出、上次价格、变化百分比、时间轴和官方链接。未知道官方生效时间时写“检测到变化”，不伪造生效时间。
- 暂时不可核验的旧有效价继续排名并带状态；unknown 不参与默认排名。
- 提供构建时生成的 `/data/catalog.json` 和 `/data/price-history.json`。浏览器不会请求厂商价格页。
- 汇率仍为 v2.0 明确披露的人工参考配置 $1=¥7，现已独立存储来源说明和更新时间；它不是实时外汇报价。

## DoD 未完成/尚不能确认的部分

**尚不能声称整个 v2.1 已完成上线验收。**

- 当前本地仓库无远端地址、无初始 Git 提交。GitHub CLI 登录已确认有效，但未指定要发布的仓库，因此没有实际 GitHub runner 执行记录、异常审核 PR 或 Pages 部署地址。

- 构建失败的数据恢复有测试；远端 Pages 失败保留旧版本只具备工作流发布门禁，未进行实际故障演练。
