## 每个模型怎么测

1. 新开对话，选定型号。使用最高推理档位；无法设置最高档时用默认档，并记录实际设置。
2. 发送一次相同提示词，保存第一次完整回答。不追问、不重新生成、不修改代码。
3. 保存原始 HTML 或完整代码、型号及档位截图。尽量用同一台电脑和同一浏览器查看。
4. 记录平台、测试日期、工具是否开启、代码是否改过。工具无法关闭时如实注明，不把工具辅助结果标成无工具生成。

已经完成的这批无需因为整理手册而重测；缺少的资料可以补交。请求因网络、权限或超时未完成的，仍记“待补测”，不算作品 0 分。

## 怎么给分

10 分项只给 0 / 5 / 10，5 分项只给 0 / 2.5 / 5：没有做到或明显不成立给 0；基本能辨认但有明显缺陷给一半；要求达成且没有明显矛盾给满分。每个扣分项写一句具体原因，必要时附截图或时间点。

- 合理的透视、卡通夸张和遮挡不扣分，不要求侧面图把另一侧的腿、脚踏全部露出来。
- 同一个问题只扣最直接相关的一项。例如脚脱离踏板，扣“后爪与脚踏”，不再重复扣“线条与配色”。
- 原题没有明确要求动画。静态与动画分别标明形式，不因是否会动直接加减分，也不设“静态最高 39 分”等限制。若作品有动画，其中可见的结构和接触错误仍按对应项判断；未录到的过程不推断。
- 不按围巾、车篮、工具包、景色、字幕、按钮的有无加减分；这些元素只有影响结构或画面清晰度时才计入对应项。录屏、转码或播放器造成的问题不算模型错误。
- 完整原作确实无法展示有效画面，排除保存、录制和环境问题后，记作品失败 0 分。材料不全不等于作品失败。

各小项相加得到总分，同分并列，不人为拉开差距。保留“夯 90–100、顶级 75–不足 90、人上人 60–不足 75、NPC 40–不足 60、拉低于 40”的档位；不沿用 v2 的剧情和动作封顶规则。

## 这批材料如何评分

已收到 14 组 GIF 和截图，随后补交了 14 份 HTML 包。模型名称按回传表对应；截图只证明可见标签，不代表后台型号已确认。原始压缩包和初评记录保留，其中 MiniMax M3 对应“千问.gif”，Qwen 对应“千问1.gif”，不凭文件名交换作品。

原作和评分分三种状态：

- **画面观察：** 只有 GIF，或原作对应关系、评分证据仍有疑问时，先给可见画面观察分 /90，不定档。网页与 SVG 的 10 分待原始 HTML 或完整代码核验，不能记 0，也不能换算成 /100。
- **AI 作品评分：** 原作与展示作品对应、运行与 SVG 已检查、11 项均有依据后，直接合计 /100，按“夯到拉”定档，同分并列。缺失的测试日期、工具记录或源宝确认在明细中注明，不阻止已有充分作品证据的评分。
- **已复核：** 在 AI 作品评分之外，源宝已确认作品和评分，型号、同题首次生成、平台、实际档位、日期、工具与代码未改等记录也已核实。未满足时不能标“已复核”，不虚构后台身份或测试日期。

当前材料核对发现两份 DeepSeek 原作包完全相同，Gemini 3.1 的 HTML 与先前 GIF 明显不同，先保留对应关系待确认，不擅自替换作品。其他看不清或无法确认的项目也写清具体缺口，不猜分。

页面保持从夯到拉的五档连续竖线与领先作品卡片。录屏统一为 960×720、25fps，等比缩放、居中补浅灰背景，保留全部原帧和时长；原始 HTML / ZIP 保留原字节，提供受限预览与下载。播放和转码只用于展示，不修复作品、不改变评分内容。

这套评分标准是在本批作品收齐后补充的。评分前固定口径，后续不因某个模型表现强弱改变权重。不同题目或规则版本不混排；之后的新批次先固定题目和标准再测试。
